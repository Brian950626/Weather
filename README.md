# Weather

`weekcast`:預報任一地點未來一週的天氣,並說明每一天有多可信。

它不依賴單一模式,而是把三套全球系集預報(ECMWF、GEFS、AIFS,共 133 個成員)放在一起看:成員與模式意見一致時信心高,分歧時就把分歧講出來。
同時分析 250、500、700、850、925 hPa 各層的噴流、槽脊、水氣與平流,說明高空
如何影響地面的天氣。
方法來自對 [Tropical Tidbits](https://www.tropicaltidbits.com) 的研究,整理在
[docs/tropical-tidbits-notes.md](docs/tropical-tidbits-notes.md);網站的章節與用語則照
課堂上的一週天氣預報報告(先講結論 → 現況 → 綜觀演變 → 模式比較 → 逐日預報 →
不確定性 → 校驗)。

## 線上預報

**<https://brian950626.github.io/Weather/>**

枋寮、台北、台中、高雄、花蓮的一週預報,每 6 小時自動更新。同一份資料的 JSON 在
<https://brian950626.github.io/Weather/data.json>。

網站只有一個檔案,但用網址切換成四個頁面(可以直接分享某一頁的網址,上一頁也能用):

| 頁面 | 網址 | 內容 |
| --- | --- | --- |
| 總覽 | `#/overview` | 一句話的結論、所有地點的逐日分區預報表、各地的注意事項 |
| 地點預報 | `#/place/地點編號/分頁` | 上方是一週的時間軸(時段、主要影響系統、高低溫、降雨機率、信心度),下面六個分頁 |
| 即時雷達 | `#/radar` | 全球合成、日本氣象廳、中央氣象署三個來源,每 5 分鐘更新 |
| 說明 | `#/about` | 怎麼閱讀、分析流程、資料與模式的角色、名詞解釋、注意事項 |

地點預報的六個分頁,順序就是預報報告的章節:

| 分頁 | 回答什麼問題 |
| --- | --- |
| 摘要 | 這一週分成哪幾段?要注意什麼?和上次預報比改了什麼? |
| 逐日與時段 | 每一天、每個時段(凌晨、上午、下午、晚上)的天氣 |
| 綜觀分析 | 為什麼這樣報:現況由地面往上看,各時段依 500 → 850 → 250 hPa → 水氣說明,最後做垂直結構檢查 |
| 模式與系集 | 各模式怎麼說、誰和別人不一樣;系集成員散得多開;同一天的預報和前幾次比 |
| 不確定性 | 各時段的信心度與理由、替代情境(A 主要、B 另一種可能)、接下來要觀察什麼 |
| 校驗 | 過去幾天報得準不準:高低溫誤差,降雨的有對、漏報、空報 |

版面刻意和[颱風網站](https://lkt0713.github.io/Typhoon-Forecast/)不同:淺色、楷體標題、
方正的表格。顏色沿用手繪天氣圖的習慣,綠色是降雨、紅色是暖、藍色是冷。

**不必手動重新整理**:開著的頁面每 10 分鐘檢查一次,有新的預報就自動重新載入;
切回分頁時也會立刻檢查。

**查其他地點**:在「地點預報」的搜尋欄輸入地名(例如「恆春」、「Tokyo」)或座標
(例如 `22.37,120.59`),同名的地點會列出來讓你選。選定後會在你的瀏覽器裡用同一份
分析程式即時計算,約 10–20 秒;查過的地點會留在地點列,按 × 可移除。搜尋的地點
沒有保存過去的預報,所以沒有預報趨勢與校驗。

**預報趨勢與校驗**:網頁每次更新時會把上一次發布的 data.json 讀回來。最近 40 次的預報
摘要存在 data.json 的 `runs` 裡,用來比較同一天的預報是連續往同方向修正還是來回擺盪,
也用來校驗:那一天過去之後,拿 1、3、5 天前的預報和實際狀況比。「實際」用的是
Open-Meteo 的分析資料,不是測站觀測。剛啟用時紀錄還不夠,校驗頁要過一天才有內容。

網頁由 `.github/workflows/pages.yml` 在 GitHub Actions 上產生並發布到 GitHub Pages。
要換地點,修改該檔案裡的 `PLACES`。首次啟用需要在 repository 的
Settings → Pages 把 Source 設為 **GitHub Actions**,且這個流程要在 `main` 分支上才會執行。

在本機產生同樣的網頁:

```bash
python3 -m weekcast.site --out _site 台北 台中
```

## 使用

需要 Python 3.10 以上,不需安裝任何套件。

```bash
python3 -m weekcast 台北
```

```bash
python3 -m weekcast Tokyo --days 10
```

```bash
python3 -m weekcast --lat 23.47 --lon 120.96 --json
```

台灣各縣市與枋寮的地名已內建;其他鄉鎮可用「名稱@緯度,經度」(例如
`python3 -m weekcast 恆春@22.00,120.75`),國外地點用英文地名。

| 選項 | 說明 |
| --- | --- |
| `--days N` | 預報天數,1–16,預設 7 |
| `--lat` `--lon` | 直接指定座標 |
| `--models` | 只用部分模式,例如 `--models ecmwf_ifs025,gfs025` |
| `--json` | 輸出 JSON |
| `--save-raw PATH` | 把原始資料存成 `.json` 或 `.json.gz` |
| `--from-file PATH` | 改讀存下的原始資料,不連網 |
| `--no-upper` | 不做高空分析(少抓兩次資料,比較快) |
| `--no-history` | 不記錄、也不比較先前的預報 |

(這份存檔是加入 PWAT 與 CAPE 之前存的,所以這兩欄是空的;連網執行時會有數值。)

命令列報表最前面會先講結論(這一週分成哪幾段、何時轉變、要注意什麼),信心度分成
高、中高、中、中低、低五級。之後有七個部分:

- **逐日表格**:中位數與 10–90% 範圍、降雨機率(日雨量達 1 mm 的成員比例)、信心。
- **時段預報**:每天四個 6 小時時段的氣溫、天氣與降雨機率。越後面的日子,時段的
  可信度下降得比整天快(鋒面晚到半天,整天的預報仍對,時段卻會錯開)。
  資料來源的雨量是「往前累積」的(標示 15:00 的那一筆是 12–15 時的雨),程式依此
  對齊時段;在台灣(UTC+8)實際上還會再早約 1 小時,這是來源對齊 UTC 的結果。
- **重點**:冷暖變化、哪幾天有雨、大雨與強風風險。
- **天氣型態**:從海平面氣壓、850 hPa 溫度、500 hPa 高度的變化判斷鋒面、冷空氣、
  高空脊槽,解釋地面天氣為什麼變。
- **高空分析**:逐日列出各層的狀況,再用「舉升、水氣、不穩定」三種成分研判,
  並和地面的降雨機率對照(詳見下節)。
- **不確定性**:信心不高的日子,各模式各自怎麼說。
- **與上次預報比較**:距離上次執行超過 5 小時後才會出現,列出預報修正了多少;
  有三次以上的紀錄時,還會指出哪幾天「連續往同方向修正」(趨勢較可信)、哪幾天
  「來回擺盪」(模式還沒有定論)。命令列的紀錄存在 `~/.cache/weekcast/`,網頁版的
  存在 data.json 裡。

## 高空分析看什麼

| 層 | 看什麼 | 對地面的意義 |
| --- | --- | --- |
| 250 hPa | 噴流軸的位置與強度、高層輻散 | 高層空氣流出(輻散)會帶動下方空氣上升 |
| 500 hPa | 槽線、脊線相對測站的位置與移動,副熱帶高壓(5880 m) | 槽前上升、易有雨;槽後與脊下沉、穩定 |
| 700 hPa | 中層濕度 | 中層夠濕雲才能長高;乾的話只有淺層降雨 |
| 850 hPa | 溫度、濕度、風、冷暖平流 | 暖平流抬升並增溫;冷平流下沉並降溫 |
| 925 hPa | 低層風與溫度、一天之內的風向轉變 | 淺層冷空氣(如東北季風)與迎風面的水氣來源;風向突然轉成偏北,就是低層鋒面通過 |
| 整層 | 可降水量 PWAT | 整層大氣有多少水氣;50 mm 以上有雨時雨勢可能較大 |
| 綜合 | K 指數(850、700、500 hPa)、CAPE | K 30 以上或 CAPE 1000 J/kg 以上容易有雷雨 |

彙整成逐日數值時,風速取各時刻風速的平均、溫度平流逐時刻計算後再平均,而不是先把
風平均再計算:鋒面通過那天風會從西風轉成東北風,直接平均會互相抵銷(西風 4 m/s 加
東北風 7 m/s,平均起來只剩北風 2 m/s),鋒面反而看不見。

槽脊與噴流要靠水平分布才找得到,所以除了測站上空,還會抓一個十字剖面:沿測站
緯度往東西各 40°(找 500 hPa 槽線)、沿測站經度往南北各 20°(找 250 hPa 噴流軸),
每 5° 一點。南北半球與熱帶東風帶都有對應的處理。

## 雷達與預報怎麼搭配

| 想知道 | 看哪裡 |
| --- | --- |
| 接下來 1–3 小時會不會下雨 | 即時雷達回波:雨現在在哪、往哪移動 |
| 今天到後天的上午或下午 | 時段預報 |
| 三天以後 | 逐日預報與信心分數;時段只當參考 |

雷達圖只在網頁上提供(命令列沒有),資料直接由瀏覽器向各來源取得,不經過這個
repository。

## 資料來源與限制

資料來自 [Open-Meteo Ensemble API](https://open-meteo.com/en/docs/ensemble-api)
(免費、免金鑰,有每日用量上限,非商業使用)。

- 溫度是模式格點值,沒有用測站觀測校正,山區與海邊誤差較大。
- 只看單點,看不到颱風或鋒面的位置。有颱風威脅時請以中央氣象署等官方警報為準。
- 信心分數與高空研判都是經驗法則,不是驗證過的機率。
- 高空分析只有 ECMWF 的兩套系集可用(其他模式不提供氣壓層資料),水平梯度以
  5° 間距估算,只能代表綜觀尺度;噴流軸超出南北 20° 時會標示「20°+」。
  PWAT 與 CAPE 只有 ECMWF IFS 系集提供。
- 低層鋒面是從每 6 小時一筆的 925 hPa 風向判斷的,通過時間只能準到 6–12 小時;
  PWAT 沒有氣候平均可比較,50 mm 的門檻是經驗值。
- 午後雷陣雨這類小尺度對流,全球系集解析不了。
